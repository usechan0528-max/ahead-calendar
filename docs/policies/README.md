## 3. 보유기간 결정용 제안 — 아직 적용하지 않음

기간이 짧다는 이유만으로 항상 적법하거나 기술적으로 안전한 것은 아니다. 최소 필요성을 평가하고 더 이른 목적 소멸·삭제 요청이 있으면 이를 반영한다. 아래 숫자는 법정 의무가 아니라 검토를 시작하기 위한 제안이다.

| 대상 | 검토 제안 | 선행 검증 |
| --- | --- | --- |
| 종료된 알림의 제목·본문·오류 상세 | 상태 확정 후 최대 30일을 상한 후보로 검토 | 제목·본문과 중복 전송 방지에 필요한 최소 식별 기록 분리. 삭제 때문에 재발송되지 않는지 테스트 |
| 구독 해지 요청 | 필요한 확인 후 지체 없이 endpoint·키·연결 작업 정리 | 단순 “알림 끄기”와 별도의 삭제 요청 정의. 여러 기기 소유권 확인 |
| 만료·장기 비활성 구독 | 필요 소멸 즉시 정리 원칙. 실패 진단이 필요하다면 최대 7일 상한 후보 | 푸시 재등록·기존 작업 FK·과거 전송 이력에 대한 영향 검증 |
| 경로 API 제한 | 현행 일 단위 제한에 필요한 기간만 유지 | KST 날짜 경계·동시 요청 처리 후 미사용 기록 삭제 가능 시점 검토 |

| 백업 | 일괄 기간을 제안하지 않음 | 실제 D1 복구 기능·플랜·데이터 잔존과 파기 가능성 확인. 복원 시 삭제 요청 재적용 |

XP·일일 목표·개인 색상은 이용자의 서비스 기록이라는 목적과 전체 삭제 권리를 함께 설계한다. 탈퇴 후 부정 이용 방지를 이유로 원본을 무기한 남기는 구조는 채택하지 않는다. 가명 처리·해시만으로 익명정보가 된다고 단정하지 않는다.

## 4. 미확정 값 관리

문서의 `{{…}}`는 공개 전에 채울 명시적인 빈칸이다. 자동 기본값으로 채우거나 실제 기능이 있는 것처럼 게시하지 않는다.

| 묶음 | 남은 값 |
| --- | --- |
| 운영자·연락처 | `PRIVACY_CONTACT_NAME`, `PRIVACY_PHONE`, `OPERATOR_LEGAL_DETAILS` |
| 시행·대상 | `EFFECTIVE_DATE`, `MINIMUM_AGE` |
| 보유기간 | `NOTIFICATION_RETENTION`, `PUSH_RETENTION`, `ROUTE_LIMIT_RETENTION`, `SUPPORT_RETENTION`, `LOG_ITEMS_AND_RETENTION`, `BACKUP_RETENTION_AND_DELETION` |
| 국외 호스팅 | `HOSTING_RECIPIENT`, `HOSTING_COUNTRY`, `HOSTING_DATA`, `HOSTING_TRANSFER`, `HOSTING_RETENTION`, `HOSTING_BASIS`, `HOSTING_REFUSAL` |
| 국외 클라우드 | `CLOUD_RECIPIENT`, `CLOUD_COUNTRY`, `CLOUD_DATA`, `CLOUD_TRANSFER`, `CLOUD_RETENTION`, `CLOUD_BASIS`, `CLOUD_REFUSAL` |

푸시 수령자 등 복수 항목은 게시용 문서에서 실제 법인·국가별 행으로 확장한다. 계약 구조상 중복하는 호스팅/클라우드 행은 실제 위탁·재위탁 관계에 맞게 합치거나 분리한다.

## 5. 동의·공지 화면 설계 원칙

- 이용약관 동의와 개인정보 처리방침 열람 링크를 구분한다. 개인정보 처리방침 전체에 대한 하나의 필수 체크박스로 모든 수집·위탁·국외 이전을 동의 처리하지 않는다.
- 계약 이행에 필요한 처리와 동의에 근거한 처리를 항목별로 구분한다. 동의가 필요한 경우 목적·항목·기간·거부 권리·거부 효과를 제시한다.
- 선택 알림을 거절해도 일정 관리가 가능해야 한다. OS 권한, 서비스 기기 수신 설정, 개인정보 동의, 광고성 정보 수신 동의는 서로 다른 개념이다.
- 광고 발송 기능은 현재 없으므로 광고 수신 동의를 필수로 추가하지 않는다. 향후 도입 시 별도 법적 요건을 검토한다.
- 전체 삭제 안내에는 “일정·알림뿐 아니라 성장 기록과 개인 설정도 삭제 대상”임을 명시하고, 일반 일정 삭제의 XP 유지와 혼동되지 않게 한다.
- 현재 두 localStorage 키는 계정별로 분리되지 않는다. 공용 기기에서 이전 이용자의 편의 설정·일정 ID가 남을 수 있으므로 계정 전환 시 초기화 또는 사용자별 분리를 검토한다. 서버 자료의 사용자별 권한 검사와 구분한다.
- 연령·해외 처리 등 정책 선택이 정해지기 전 실제 가입 차단·동의 버튼을 임의로 구현하지 않는다.
