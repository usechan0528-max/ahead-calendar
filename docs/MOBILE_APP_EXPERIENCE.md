# 앱 특화 1차: 설치형 웹 앱 사용성

## 범위
기존 홈 화면 설치형 웹 앱을 유지한다. 네이티브 iOS/Android 프로젝트, 스토어 배포, 회원가입 전환, 오프라인 저장·자동 재전송은 이번 범위가 아니다.

- 기존 오늘/캘린더/준비/알림 메뉴 사이에 중앙 ‘추가’를 배치한다(접근성 이름: 새 일정 추가). 모바일 상단의 중복 추가 버튼은 숨긴다. 모든 아이콘 영역 높이를 맞춰 글자 기준선을 통일한다.
- 모바일 상세 화면은 상단 돌아가기로 목록에 복귀한다. 모달을 열면 배경과 하단 메뉴가 조작되지 않는다.
- 공통 작성 모달은 고정 제목/닫기, 단일 내용 스크롤, 고정 저장 영역으로 나눈다. 기존 미저장 변경 확인과 포커스 가두기를 유지한다.
- VisualViewport의 높이·위치에 작성창을 맞추고 축소/확대는 키보드로 판단하지 않는다. 미지원 환경은 일반 viewport/dvh로 동작한다.
- 네 방향 safe-area를 반영한다. 하단 메뉴 실제 높이를 측정하여 큰 글씨에서도 본문·토스트가 겹치지 않도록 공간을 확보한다.
- 연결 상태는 알림 요청 잠금과 독립적으로 읽는다. 기기 오프라인 신호를 보여주되 서버 연결 성공으로 해석하지 않는다. 오프라인 작성 내용은 열린 화면의 메모리에만 남고, 새로고침 후 복구를 약속하지 않는다.

## 검증

UI 정돈: 작성창은 제목 입력부터 시작하고 중복 소개·알림 요약을 줄인다. 접이식 설정과 알림 도움말은 같은 방향 표시를 쓴다. 알림 재점검 중에는 마지막 결과를 유지하며 점검 버튼으로 갱신 중임을 표시한다. 최초 조회는 로딩 상태, 새로 확인된 실패는 오류 상태로 표시한다.
`scripts/test-mobile-app.mjs`에서 하단 메뉴 액션/선택/숨김, SSR 폼 구조, 키보드·회전·확대 상태 계산, viewport 이벤트 정리, 실제 메뉴 높이, 독립 연결 이벤트, safe-area/확대 접근성을 점검한다. 실기기 렌더링·키보드·회전 동작은 이 테스트로 대체되지 않는다.

실기기 확인: iPhone 홈 화면 앱과 Safari, Android 홈 화면 앱과 Chrome에서 일정 추가 → 긴 폼 입력 → 키보드 표시/닫기 → 세로/가로 전환 → 저장 또는 변경 취소 → 상세 복귀. 큰 글씨/화면 확대, 비행기 모드에서 입력 유지와 명시적 재저장도 확인한다.
