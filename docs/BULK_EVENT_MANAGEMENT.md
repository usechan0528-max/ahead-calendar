# 일정 일괄 관리

캘린더의 **일괄 관리**에서 실제 저장된 일정만 조회한다. 기존 월간/목록 화면은 유지한다. 한 번에 최대 20개, 일정당 한 회차를 선택한다.

## 작업 범위

- 완료 처리 / 완료 해제: 표시된 `originalDate` 회차만 적용. 시작 전 일정의 완료는 불가. 기존 경험치 중복 지급 방지와 하루 상한 유지.
- 종류 변경: 선택한 일정의 반복 전체에 적용. 사용자 입력 종류/색상 체계를 재사용하며 준비 항목, 위치와 이동 계획, 알림과 회차별 변경을 보존.
- 날짜 이동: 1~365일 앞/뒤. 반복이 없고 실천 이력이 전혀 없는 일정만 허용. 완료 해제 기록, 준비 완료 기록, 0 XP 지급 영수증도 실천 이력이다. 시작/종료일을 같은 간격으로 이동하며 시간과 기간을 유지한다.
- 삭제: 반복 전체, 준비 항목/알림/회차별 기록을 외래키로 함께 삭제. 독립적인 경험치 지급 원장은 유지. 실행 직전 제목과 건수, 반복 전체 삭제 여부를 확인하며 복구 불가 안내.

## 안정성

- 서버 인증에서 소유자를 정하고 표시된 목록의 계정 범위를 요청에 결합한다. 다른 계정으로 전환한 이전 화면은 거절한다.
- 동일 출처, 전용 헤더, JSON, 8 KB 제한, 전체 요청의 ID/날짜/버전/종류 검증 후에만 쓰기 시작.
- 각 일정은 소유자와 선택 당시 버전을 검사. DB 변경 또한 버전을 조건으로 적용하여 다른 화면의 수정을 덮어쓰지 않는다.
- 날짜 이동 가능 여부는 완료/XP 기록 검사를 포함한 동일 트랜잭션으로 검사한다. 동시에 완료하면 한 쪽의 이전 버전 변경은 거부한다.
- 일정 간 전체 원자성은 보장하지 않는다. 각 일정의 성공/미처리/결과 불확실을 구분하고 실패 선택을 화면에 남긴다.
- 전송 오류나 저장 후 조회 오류를 롤백으로 간주하지 않는다. 자동 재시도하지 않으며 다음 작업 전 최신 목록을 불러오도록 한다.
- 필터 밖 선택 건수 표시. 기준일/새로 불러오기 시 선택 초기화. 오프라인/처리 중 쓰기 제한.

DB 스키마 변경과 외부 유료 서비스 연결 없음. 실제 회원 데이터가 아닌 격리된 DB에서 검증한다.
