# To J 사용 흐름 — 3차 구현

2026-09-20. 범위: 오늘 우선 진입 → 간단한 일정 등록 → 선택형 준비와 명시적 알림 수신 설정.

2차: 상세에서 준비·완료로 바로 연결 → 완료 기록 확인 → 오늘 또는 다음 일정으로 명시적 이동.

3차: 지난 일정 정리 · 알림 후 행동 · 하루 마무리 · 기념일 단계별 준비 · 이 브라우저에서 이어보기.

## 오늘

- 첫 화면과 로고는 ‘오늘’로 연결한다. 일정이 없는 계정은 첫 일정 만들기 또는 예시 캘린더 둘러보기를 선택한다. 예시를 실제 오늘 할 일처럼 표시하지 않는다.
- 등록된 일정은 진행 중인 미완료 회차, 없으면 가장 가까운 다음 미완료 회차를 강조한다.
- 오늘 남은 일정 → 다가오는 일정의 저장된 준비 항목 → 오늘 완료한 일정 → 성장 기록 순서다. 지난 미완료 일정은 지우지 않고 ‘시간 지남’으로 남긴다.
- 준비 목록의 항목 수는 완료율이나 실제 기한이 아니다. 준비 시점 메모와 푸시 알림을 구분한다. 준비를 끈 일정과 완료된 회차는 미리 챙길 준비에서 제외한다.
- 화면 계산과 선택은 기존 원회차 식별자를 사용한다. XP, 완료 규칙, 반복 계산은 변경하지 않는다.

## 일정 등록

- 제목·날짜/시간·알림 요약을 먼저 제공한다. 일반 추가는 현재 한국 날짜, 캘린더에서 추가는 선택 날짜를 쓴다.
- 종류·장소/경로·준비·반복·메모는 펼쳐서 설정한다. 기존 값이 있는 장소·반복·메모는 수정 시 펼쳐서 보여준다.
- 접힌 입력도 계속 마운트하여 제출·미저장 변경 감지에 포함한다. Tab으로 펼치기 버튼에 접근하고, 유효하지 않은 입력은 해당 영역을 펼친다.
- 알림 기본 3회와 사용자가 기억한 브라우저별 기본값은 유지한다. 알림 없음·한 번·여러 번의 기존 기능은 유지한다.
- 신규 UI는 `seedPreparations: false`를 POST에 전달한다. 준비 사용이 켜져도 체크리스트는 비어 있으며, 추천을 직접 담거나 항목을 추가한다. 필드를 생략하는 이전 클라이언트는 기존 템플릿 3개 생성 동작을 유지한다.
- 기존 일정 PATCH에는 생성 전용 필드를 보내지 않는다. 기존 체크리스트·완료·알림은 그대로 유지한다. 마이그레이션이나 기존 기록 정리는 없다.

## 저장 후

- 성공한 신규 일정의 정확한 회차 상세에서 저장 안내를 보여주고 초점을 이동한다. 수정에는 이 안내를 반복하지 않는다.
- 준비 사용 시 ‘준비 항목 고르기’, 알림 시점이 있으면 ‘알림 수신 설정/알림 확인하기’, 항상 ‘오늘로 가기’를 제공한다.
- 준비 사용 안 함이면 준비 선택을 재촉하지 않는다. 알림 없음이면 기기 권한 설정을 재촉하지 않는다.
- 알림 시점 저장과 기기의 수신 상태를 별도로 표시한다. 권한 요청이나 테스트 푸시는 저장 과정에서 호출하지 않는다.
- 알림 수신 설정 버튼은 기존 설정 화면으로만 연결한다. 실제 켜기는 사용자의 명시적 동작으로 진행하며 모든 일정에 대한 기기 수신임을 안내한다.
- 준비 추천은 규칙 기반이며 날씨나 유료 AI 연결을 포함하지 않는다. 준비를 담는 동작은 완료 처리나 알림 예약을 뜻하지 않는다.

## 범위 밖

공개 가입·소셜 로그인, 네이티브 앱 배포, 자유 입력 알림 미루기, 추천 전체 끄기의 별도 계정 설정은 이번 작업에 포함하지 않는다. 기존 준비 숨기기와 추천별 숨기기는 유지한다.

## 상세에서 실행하고 돌아오기

- 상세 제목·날짜 다음에 현재 할 수 있는 행동을 표시한다. 지도·반복 관리·긴 추천 목록보다 위에서 준비와 완료에 접근한다. 신규 저장 직후에는 기존 저장 안내만 표시하여 중복을 피한다.
- 시작 전에는 완료 버튼을 표시하지 않는다. 준비 사용 시 목록을 확인할 수 있으며, 체크 가능 여부는 서버의 기존 규칙을 따른다. 준비 사용 안 함이면 준비 추가를 재촉하지 않는다. 빈 체크리스트의 추천 연결은 선택한 회차가 추천 기준 회차일 때만 우선하고, 그렇지 않으면 직접 체크리스트로 연결한다.
- 시작 후에는 서버의 `canCompleteEvent`에 따라 완료 버튼을 표시한다. 준비 잔여 개수를 안내하지만 모든 준비 완료를 일정 완료 조건으로 만들지 않는다. 조회 중·오류는 미완료로 단정하지 않고 확인 중·재시도를 표시한다.
- 오늘의 ‘미리 챙길 준비’, 준비 목록, 캘린더 준비 배너는 정확한 원회차의 체크리스트로 초점과 스크롤을 이동한다. 알림 진입도 기기 설정 위치로 이동하지만 권한 요청·동의 변경·발송은 하지 않는다.
- 완료 상태는 저장된 서버 기록에서 표시한다. 저장 실패 시 성공 안내·자동 이동 없음. 완료 후 오늘로 돌아가기 또는 진행 중·다가오는 미완료 일정 보기 중 직접 선택한다. 다음 일정이 없다고 지난 미완료 일정까지 모두 끝났다고 단정하지 않는다.
- 다음 일정은 예시·완료·취소·종료된 회차를 제외하고 진행 중을 우선한다. 반복 일정의 다음 회차도 가능하며, 이동된 날짜가 같아도 원회차 날짜로 구분한다.
- 완료 체크 취소는 ‘잘못 체크했나요?’를 펼쳐 접근한다. 기존 XP 보존·중복 지급 방지는 그대로다. 준비 완료와 일정 완료는 별도이며, 재진입 시 축하를 재생하지 않는다.
- 완료 저장 중 다른 일정으로 이동하면 저장 응답이 새 상세로 초점을 빼앗지 않는다. 저장 실패 시 성공 안내 대신 오류 안내에 초점을 둔다. 초점 요청은 한 번만 처리하여 모달을 닫을 때 원래 버튼으로의 초점 복원을 방해하지 않는다.
- 추가 데이터베이스·알림·외부 API 없음. 현재 성장 규칙·사용자 기록·알림 수신 설정을 변경하지 않는다.

## 검증

- 3차 사용성 테스트: 지난 7일 경계/기간/이동/취소/완료 회차, 오래된 일일 기록 제외, 내일 진행 중 일정, 브라우저 기록 검증, 명시적 이어보기, 기념일 메모와 기존 수정 보존, 알림 클릭 무변경 및 명시적 확인·미루기.
- 3차 격리 Worker/D1 테스트: 단계별 시점 메모 입력 검증·동시 채택 중복 방지·준비 옵트아웃·삭제 기록 보존, 10/30/60분 미루기·본문 토큰·동시 확인/미루기·수신 동의 철회·일정/경험치 불변·원회차 식별자와 새 발송 만료 구간 보존.

- 사용성 테스트: 오늘/종료/이동/겹친 회차, 준비 숨김, 접힌 입력 렌더링, 저장 안내 16개 분기, 명시적 알림 동의.
- 격리된 Worker/D1 테스트: 이전 클라이언트 호환, 생성 전용 옵션 검증, 준비가 빈 일정 저장 → 추천 읽기 → 한 항목 채택 → 수정 보존, 기기 동의 변경 없음.
- 브라우저 실기 테스트는 별도로 요청할 때 실행한다. 자동 테스트에서 실제 사용자 일정이나 실제 푸시를 사용하지 않는다.
- 2차 사용성 테스트: 안내 상태별 렌더링, 명시적 버튼 콜백, 준비 화면 진입, 준비 옵트아웃, 회차별 다음 일정 선택, 실패/로딩/예시/최종 반복/겹친 회차/같은 날짜로 옮긴 회차와 중복 완료 버튼 방지.

## 지난 일정 정리

- 오늘 화면의 ‘지난 일정 확인’을 직접 펼친다. KST 기준 어제부터 7일 전까지 끝난 실제 일정 중 서버 완료 기록이 없는 회차를 표시한다. 오늘 끝난 일정과 아직 진행 중인 기간 일정은 이 목록에 섞지 않는다.
- 최초 5개와 5개 더 보기를 제공한다. ‘일정 정리하기’는 원회차 상세로 이동하며, 실제로 완료했으면 기존 완료 버튼을 사용한다. 반복 일정은 해당 회차 날짜만 수정하고 일반 일정은 기존 편집기를 사용한다.
- 기념일은 원래 날짜를 옮기도록 유도하지 않는다. 후속 연락 계획 초안을 일반 일정으로 열고, 사용자가 저장해야 생성한다. 제목은 100자 제한을 지키며 기존 알림 기본 설정을 바꾸지 않는다.
- 그대로 두고 오늘로 돌아갈 수 있다. 미완료에 대한 감점·삭제·자동 이월은 없다. 지난 계획을 오늘 처음 완료한 보상과 목표는 기존 서버의 오늘 기준을 따른다.

## 알림에서 이어하기

- 알림 본문을 열면 일정·원회차·알림 ID를 서버 기록과 대조한다. 열기 자체는 알림 확인, 계획 완료, 경험치 지급을 실행하지 않는다.
- 사전 알림은 준비가 켜져 있으면 준비 목록, 그 외 장소가 있으면 장소·경로, 없으면 일정 내용으로 연결한다. 테스트 알림은 알림 상태로 연결한다. 사용자 선택으로 이동하며 준비 옵트아웃을 존중한다.
- 발송된 알림에서 명시적 확인 또는 10/30/60분 ‘알림만 미루기’를 선택한다. 일정 날짜·시간·준비 마감은 변경하지 않는다. OS 알림 버튼의 10분 동작과 이전 클라이언트의 본문 없는 요청은 호환된다.
- 미루기는 기존 소유권/알림 토큰, 수신 동의, 현재 회차/규칙과 원자적 상태 검증을 따른다. 미루기를 중복 제출해도 한 번만 예약하며 실제 기기 도착 시간을 보장하지 않는다.
- 없는 알림·다른 회차·조회 실패에는 안내 또는 재시도를 제공한다. 늦은 조회/미루기 응답이 새 선택이나 최신 알림 상태를 덮어쓰지 않도록 요청 세대를 구분한다.

## 하루 마무리

- 오늘의 ‘하루 정리 · 내일 미리 보기’를 필요할 때 펼친다. 오늘 일정 중 완료/남은 개수와 오늘 획득 XP를 분리한다. 지난 계획에서 오늘 얻은 XP도 포함됨을 안내한다.
- 완료 기록 조회 실패나 KST 날짜가 지난 요약은 0으로 단정하지 않고 다시 확인한다. 남은 일정은 상세에서 정리하며 자동으로 다음 날에 옮기지 않는다.
- 내일 목록은 내일 시작하는 일정뿐 아니라 내일까지 이어지는 기간 일정도 포함한다. 준비를 끈 일정에는 준비로 가는 버튼을 표시하지 않는다. 별도 회고 알림을 자동 생성하지 않는다.

## 기념일 단계별 준비

- 생일/기념일/축하 추천에서 축하 방법(14일 전), 예약(7일 전), 마음 전하기(당일)를 제안한다. 각 단계의 시점은 0~365일 전 메모로 바꿔 하나씩 담는다. 일부만 선택할 수 있다.
- 시점은 체크리스트의 텍스트 메모이며 날짜형 마감이나 자동 알림이 아니다. 알림은 추천별 설명·알림 설정 또는 일정의 알림 탭에서 별도로 선택한다.
- 이미 담은 준비는 실제 저장된 시점을 표시하고 수정은 체크리스트에서 한다. 재선택·재시도·동시 요청은 기존 항목/수정/완료를 덮어쓰거나 중복 생성하지 않는다. 숨긴 추천과 삭제한 준비를 자동 복구하지 않는다.
- 반복 준비 목록과 시점 메모는 기존처럼 전체 일정에 공유된다. 선택만으로 완료·경험치·푸시 발송이 생기지 않는다.

## 이 브라우저에서 이어보기

- 마지막 열람 위치만 `to-j:last-view:v1`로 브라우저에 기억한다: 버전, 서버 일정 ID, 원회차 날짜, 허용된 상세 영역. 저장 성공과 상세/준비/알림/장소 진입 시 갱신한다.
- 재방문 시 현재 로그인 사용자의 서버 일정과 완료 기록을 받은 뒤 카드로 제안한다. 자동 이동하지 않으며 알림 딥링크가 있으면 우선한다. 제목·내용·완료 상태·계정 토큰을 로컬 기록에 넣지 않는다.
- 삭제/취소/다른 계정의 일정은 열지 않고 일반 안내만 표시한다. 준비를 끈 일정의 준비 위치는 일정 요약으로 대체한다. 완료 기록은 서버에서 읽고 재보상하지 않는다.
- ‘기억 지우고 오늘 보기’로 로컬 위치를 지울 수 있다. 로컬 저장소 사용이 차단돼도 일정 기능은 계속 사용할 수 있다. 다른 기기 간 동기화나 오프라인 편집 기능은 아니다.
