# J에게 (To J) 기능 명세와 개발 순서

기준일: 2026-09-20. 국내 우선 출시를 준비하는 개인 일정·기념일·알림·계획 실천 서비스.
서비스명 J에게 (To J). P에서 J로 계획 습관이 성장하는 콘셉트. 최종 목표는 웹·iOS·안드로이드 공통 서비스이며 공개 출시나 외부 계정 연동은 별도 결정이 필요하다.

## 제품 원칙

- 일정 확인 → 준비 → 알림 설정의 흐름이 짧고 명확해야 한다.
- 자동 생성은 시작점이다. 사용자가 내용을 수정하고 제거할 수 있어야 한다.
- 실제 발송, 예상 시각, 준비 메모, 추천을 구분한다.
- 계정별 데이터와 기기별 알림 동의를 보존한다. 사용자 동의 없이 알림을 켜지 않는다.
- 일반 문구는 쉽게 쓰고, 설정은 필요할 때만 펼친다.

## 2. 구현된 세부 동작

### C1/E1/G1 기본 사용성 보호

- 작성·수정 중 변경이 있으면 닫기 버튼, 바깥 클릭, Escape에서 확인한다. ‘계속 작성’은 폼을 유지하여 제목·메모·날짜·반복·준비 표시·장소·경유지를 보존한다. 변경 없는 폼은 바로 닫는다.
- 저장 중 입력·닫기·중복 제출을 막고, 실패 시 입력을 유지한다. 미저장 내용이 있을 때 새로고침·페이지 이탈에는 브라우저 기본 경고를 요청한다. 브라우저 강제 종료 후 초안 복구나 영구 임시 저장은 제공하지 않는다.
- 오늘 화면은 KST 오늘에 걸친 실제 회차를 ‘오늘 남은 일정’과 ‘오늘 일정 중 완료’로 구분한다. 종료 시간이 지난 미완료 회차는 ‘시간 지남’으로 남기며, 겹친 반복 회차도 각각 집계한다. 완료 취소 시 남은 일정으로 돌아온다.
- 저장 성공 시 해당 날짜·월을 선택하고 검색·종류 필터를 초기화한다. 신규 또는 시작 날짜 변경은 첫 유효 회차를, 시작 날짜와 반복 규칙이 같은 기존 수정은 보고 있던 유효 회차를 유지한다. 반복 규칙만 바뀌면 현재/다음 회차를 표시한다. 일반 월 이동이나 상세 열기에는 이 이동을 강제하지 않는다.
- 이 개선은 기존 알림 설정·XP·준비 저장 규칙과 데이터베이스 구조를 바꾸지 않는다. 유료 AI 추천 연결은 보류한다.

### E1/E3 종일·기간 일정

- 종일 여부와 종료 날짜·시간은 선택 사항으로 두고 필요한 입력만 펼친다.
- 종일 종료 날짜는 포함한다. 시간 지정 일정은 종료 시각 미만까지이며 다음 날 00:00에 끝나면 다음 날짜 셀에는 표시하지 않는다.
- 시작일과 종료일의 간격은 최대 366일이다. 음력이나 시간대별 변환은 추가하지 않는다.
- 여러 날 일정은 월을 넘어도 해당 날짜마다 보이고, 상세 열기는 그 회차의 실제 시작 날짜를 유지한다. 월간 건수는 날짜 칸 수가 아니라 회차 수다.
- 반복 일정의 시작 날짜에 기존 반복 규칙을 적용하고, 종료는 원래 시작~종료의 일수 간격을 유지한다. 겹치는 회차도 별도로 표시한다.
- 진행 중인 시간 지정 일정은 실제 KST 시작·종료 시각으로 판정한다. 목록은 진행 중 회차를 우선하고 없으면 다음 회차를 표시한다.
- 알림·사전 준비 추천은 해당 회차의 시작일 기준이다.
- 종일 알림 기준은 기본 09:00이며 사용자가 바꿀 수 있다. 기존 `event_time`은 보존하고 종일 기준 시각을 별도 저장한다.
- 알림은 회차 시작 기준의 각 시점에 한 번만 계획한다. 화면에서 여러 날짜에 보이는 것이 매일 알림을 뜻하지 않는다.
- 기존 일정은 시간 지정/종료 없음으로 보존하며, 기간 속성을 모르는 이전 클라이언트의 수정에서도 새 속성을 유지한다.

### N1 생성 시 알림 선택

- 새 일정 작성에서 알림 없음, 한 번, 기본 3회(1주·1일·2시간 전), 직접 설정을 선택한다. 한 번/직접 설정은 분·시간·일·주 단위로 입력하며 분으로 환산한다.
- 처음에는 기존 기본 3회가 선택된다. 사용자가 브라우저 기본값 기억을 체크하고 생성에 성공했을 때만 mode/offsets를 이 브라우저의 UI 선호로 저장한다. 다음 생성에만 적용하며 기존 일정·다른 기기로 동기화하지 않는다. 체크 해제 후 생성 성공 시 기억을 지워 기본 3회로 돌아간다. 취소·실패는 기억을 바꾸지 않는다.
- 실제 일정별 알림은 서버에 영구 저장한다. 새 `initialReminderOffsets` 입력은 0~525600분 정수의 중복 없는 최대 10개 배열이며, 명시적 빈 배열은 알림 없음이다. 생략하는 이전 클라이언트는 기존 기본 3개를 유지한다. 생성 전용 입력으로, 기존 일정 PATCH에서는 알림을 덮어쓰지 않는다.
- 일정·선택 알림·기본 준비 항목을 하나의 트랜잭션으로 생성한다. 알림 없음과 준비 항목 끄기를 함께 선택해도 저장되며, 자식 저장 실패 시 일정도 함께 되돌린다.
- 저장은 기기 수신 동의를 변경하지 않는다. 수신 꺼짐, 이미 지난 시점, 종일 기준 시간, 반복 회차별 적용을 안내한다. 기존 예약기가 동의한 기기에 선택한 시점만 예약한다.

### N2 개별 알림

- 저장된 각 시점을 목록으로 보여 주고 수정/삭제한다.
- 분·시간·일 단위 입력을 지원하며, 0은 시작 시각이다. 종일 일정은 별도 알림 기준 시각을 사용한다.
- 같은 알림 시점은 중복 추가되지 않는다. 기존 시점과 겹치는 수정은 거절하고 원래 설정을 유지한다.
- 프리셋은 개수가 아니라 실제 시점 조합이 일치할 때만 선택 표시한다.
- 삭제는 한 번 더 확인한다. 마지막 알림을 삭제할 때 자동 발송이 없어짐을 안내한다.
- 변경은 같은 계정의 해당 일정에만 적용한다.
- 실제 변경과 revision 증가·대기 예약 취소는 한 트랜잭션으로 처리하고 새 규칙으로 재계획한다.
- 존재하지 않는 항목, 권한 없음, 중복 충돌, 같은 값 저장은 유효한 예약을 취소하지 않는다.
- 이미 발송/확인한 이력은 유지한다. 이미 외부 전송을 시작한 알림의 회수를 약속하지 않는다.
- 화면의 예상 시각은 한국 시간으로 계산한다. 기기가 꺼져 있거나 지난 시각이라면 발송 보장으로 표현하지 않는다.

### P2 준비 편집

- 자동 항목과 직접 추가한 항목 모두 수정·삭제할 수 있다.
- 제목은 1~160자, 준비 시점 메모는 1~60자다.
- 제목·메모 수정은 완료 여부를 보존한다.
- 마지막 준비 항목도 삭제할 수 있다. 빈 상태에서 새로 추가할 수 있다.
- 준비 편집은 알림 규칙, 발송 예약, 기기 수신 동의를 변경하지 않는다.
- 저장 중 중복 클릭을 막고, 실패한 입력은 수정 후 다시 저장할 수 있게 유지한다.
- 예시 일정은 실제 데이터처럼 저장된 것으로 안내하지 않는다.

## 3. 개발 순서

| 순서 | 묶음 | 완료 기준 |
| --- | --- | --- |
| 1 — 완료 | 알림 개별 제어 + 준비 편집 | 영구 저장, 권한 격리, 중복/오류/예약 취소 테스트 통과 |
| 2 — 완료 | 종일·종료 시간·여러 날 일정 | 기간 표시·알림 기준 일치, 기존 시간 보존, 겹친 회차 및 중복 알림 검증 |
| 3 — 이번 개발 | To J 브랜딩·회차별 완료·성장 공통 기반 | 중복 지급·하루 상한·기존 기록 보존·원자적 저장 검증 |
| 4 — 다음 제안 | 모바일 알림 검증·출시용 인증/API 설계 | iOS/Android 실기 알림, 계정 매핑과 동기화 계약 검증 |
| 5 — 다음 제안 | 반복 종료·회차별 변경 | 한 번만/이후/전체 편집 구분, 취소 회차 알림 방지 |
| 4 — 후속 | 알림 사용성 고도화 | 일정별 일시정지, 미루기 시간 선택, 전용 알림 기록 화면 |

‘다음 제안’은 이번 배포에 포함하지 않는다. 동기화·공유·유료 서비스 연결은 따로 범위와 권한을 정한다.

2026-09-20 사용 흐름 1차: 기본 진입을 오늘로 변경하고, 등록 선택 설정을 접으며, 신규 저장 후 준비·알림 안내를 연결한다. 신규 UI는 기본 준비 항목을 자동 생성하지 않는다. 기존 알림 기본값과 저장 기록은 보존한다. 자세한 범위는 `USER_FLOW.md`에 있다.

사용 흐름 2·3차: 상세의 준비→완료→다음 행동, 최근 7일 지난 일정 정리, 알림별 다음 행동과 10/30/60분 미루기, 선택형 하루 정리/내일 미리 보기, 기념일 단계별 준비 메모, 이 브라우저에서 마지막 열람 위치 이어보기를 제공한다. 강제 이월·자동 완료·자동 알림 동의·보상 규칙 변경은 없다. 공개 가입·네이티브 앱 출시와는 구분한다.

## 4. 현재 운영 경계

- 계정별 영구 저장을 사용하며 공개 가입형 서비스로 전환하지 않았다.
- UI와 일정 시각은 한국 시간(KST) 기준이다.
- 페이지가 닫혀도 서버에서 알림을 발송한다. 브라우저/운영체제의 수신 정책에 영향을 받는다.
- 기기에서 일정 알림을 켠 뒤의 시점만 대상으로 한다. 30분 넘게 늦어진 자동 알림은 보내지 않는다.
- 각 규칙 시점에 한 번 발송하며, 사용자가 원하면 화면에서 10/30/60분 중 선택해 미룬다. OS 알림의 빠른 동작은 10분이다. 일정 시간은 그대로이며 확인 전 자동 반복은 구현하지 않았다.
- 추천은 진행 중 또는 다음 회차를 기준으로 하며, 다른 반복 회차를 선택했을 때 이를 구분해 안내한다.
- 반복 준비 항목의 제목·시점은 전체에 공유되며 완료 여부는 회차별이다.
- 경험치는 첫 완료 영수증에만 지급된다. 취소·삭제해도 이미 받은 XP는 유지하고 다시 지급하지 않는다. 자세한 규칙은 `TO_J_ARCHITECTURE.md`에 있다.
- 결제·구매·예약 자동 실행, 의료 조언, 근태·급여 관리, 기업용 자원 배정은 이번 범위가 아니다.

- 표시: 모든 반복 회차, 날짜 이동, 빈 결과, 월간·목록 탐색.

- 준비: 추가→완료→수정→삭제 및 완료/제목 동시 변경 시 보존.

## 반복 종료와 회차별 변경 (2026-09-20)

- 반복 종료일은 원래 회차의 시작일 기준이며 해당 날짜를 포함한다. 비워 두면 계속 반복한다. 종료일로 모든 회차가 사라지는 잘못된 최초 규칙은 저장하지 않는다.
- `eventId + originalDate`는 회차의 고정 식별자다. 실제 표시 날짜와 분리하며, 날짜를 옮겨도 완료·준비 체크와 경험치 영수증을 새로 만들지 않는다.
- 상세의 **이번 회차 수정**은 제목, 시작·종료 날짜/시간, 종일 여부, 알림 기준 시간, 메모를 저장한다. 장소·이동 경로·준비 목록·알림 간격은 전체 일정 설정을 상속한다. 회차별 수정은 전체 수정 내용보다 우선한다.
- **이번 회차 취소**는 해당 회차를 달력·오늘 목록·다가오는 추천에서 제외하고 아직 보내지 않은 알림을 무효화한다. 완료·XP 기록은 보존하고, 변경·취소 내역의 **원래대로**는 전체 일정의 기본 내용으로 복구한다. 이미 발송된 알림은 회수하지 않는다.
- 반복 종료일을 줄여도 회차 예외와 과거 보상은 삭제하지 않는다. 종료일 뒤 원회차에 연결된 이동 예외도 표시·발송하지 않는다. 종료일을 늘리면 다시 유효해질 수 있다.
- 회차 예외 기록이 있는 일정은 고정 식별자 보호를 위해 시작 날짜와 반복 종류·간격·요일/일자 변경을 막는다. 종료일, 제목, 시간, 장소 등 나머지 전체 설정은 수정 가능하다. 새 반복 규칙이 필요하면 별도 일정을 생성한다.
- 일정당 최대 500개 원회차 변경 기록을 저장한다. 원래대로 복구한 기록도 알림 소급 발송 방지용 시각을 보관한다. 전체 일정 삭제 시 예외는 함께 삭제한다.
- 알림 키는 원회차·알림 간격·기기로 고정한다. 이전 버전의 날짜/시간 기반 예약은 같은 원회차로 연결하며, 중복된 옛 예약은 대표 예약만 조회·발송·미루기가 가능하다. 시각 변경 시 미발송 예약의 본문·실제 시각을 갱신하고 발송 이력을 재생하지 않는다.
- 회차 변경, revision 증가, 알림 무효화는 D1 원자적 배치로 처리한다. 다른 회차의 미루기 상태를 보존하고, 전체 수정과 회차 수정의 경합은 409로 차단한다.
- 유료 AI 기능은 도입하지 않는다. 규칙 기반 준비 추천은 변경을 반영한 현재/다음 회차를 기준으로 한다.
- 검증: `scripts/test-occurrences.mjs` (격리 D1/프로덕션 API), 기존 알림·완료·기간·준비 추천·사용성 회귀 테스트, Chrome에서 임시 일정 생성→다른 달 이동→취소→복구→임시 데이터 삭제.
